## Fixture coverage and constraints

The new pure scope policy rejects no tenant, inactive/mismatched membership, unsupported action–target, missing target, conflicting or cross-tenant candidate, malformed proof and actor/metadata/browser spoof. It uses `TenantContext` as input only; only `RolesGuard` is allowed to produce that context in production. Its fixture allowlist is not exported as a production mapping. No provider, payment or database read occurs. No cursor scanner or migration exists; therefore cursor, batch, total, isolated MySQL and migration behavior cannot be claimed tested.

**Separate security items:** `apps/api/src/auth/jwt.strategy.ts` lacks issuer/audience contract; `workers/cron-jobs/src/audit-integrity-check.ts` scans without take/cursor and logs order IDs. Future work needs distinct approvals and tests.

**Side effects:** no provider call, payment action, deployment, production/shared/disposable DB operation, fulfillment, provisioning, entitlement or historical audit change. No browser files or dependencies changed.
